# Building memory packs

Use for a bounded pre-project or maintenance exercise that should make later agents faster
and more consistent. A pack consists of a complete, reviewable evidence artifact plus a
small set of governed memory candidates that point into it. It is not a dump of everything
found and does not turn observations into authority.

## When NOT to load

Do not load for ad hoc memory capture, ordinary task learning, unapproved source
harvesting, or when no complete reviewable evidence artifact is required.

## Establish the pack contract

1. State the intended future tasks, consumers, project/trust domain, approved sources,
   exclusions, source rights, revision identities, and freshness horizon.
2. Define useful categories for the source set, such as architecture and ownership,
   invariants, interfaces, data grain and lineage, operational procedures, failure patterns,
   validation commands, decisions, preferences, and known hazards.
3. Exclude credentials, personal data, employer/client material outside its authorized
   domain, generated noise, unsupported inference, generic advice, and duplicated content.
4. Define stop conditions and an evidence budget before broad inspection. Deep analysis is
   useful only when its provenance remains reviewable.

## Build the evidence artifact

Inspect authoritative sources directly and challenge each material inference. Preserve a
complete report or notebook with source identity, revision/time, methods, observed facts,
interpretations, uncertainty, contradictions, sensitivity screening, and revalidation
conditions. Keep detailed examples and explanations there rather than bloating retrieval.

## Build the retrieval index

1. Select only claims likely to change a future decision or prevent repeated discovery.
   Start with 10 to 30 high-signal candidates; fewer is better than low-signal coverage.
2. Apply `authoring-governed-memories` to every candidate. Each must be atomic, narrowly
   scoped, provenance-linked, searchable, candidate-only, and independently challengeable.
3. Deduplicate semantically, not only by exact text. Preserve complementary claims only
   when each has a distinct retrieval purpose.
4. Use typed verification for supported mechanical facts. Keep preferences and policy tied
   to explicit human or governing-record authority.
5. Load `auditing-memory-governance` for the independent pack review: trust isolation,
   sensitivity, provenance, duplicates, retrieval quality, lifecycle eligibility, and
   installed/public-path behavior where applicable.
6. Qualify bounded output against the complete eligible project-scoped corpus. A relevant
   older memory must not disappear merely because an arbitrary SQL prefix was ranked first.

## Qualify usefulness

Run at least three representative real tasks when practical. For each, record which memories
were selected, whether they were relevant, whether they changed work, the source evidence
used to verify them, false positives, important misses, and time or rediscovery avoided.
Disposition every selection truthfully. Improve or quarantine weak candidates; do not tune
claims merely to manufacture retrieval hits. Expand the pack only when measured misses show
a recurring gap. Evaluate ranking from immutable applications and evaluations, not legacy
mutable use, surface, application, or confirmation counters.

## Maintain the pack

Revalidate on its declared trigger: source revision, architecture or policy change,
scheduled freshness boundary, contradiction, or repeated retrieval failure. Supersede
replaced knowledge with lineage and quarantine unsafe or invalid knowledge through public
lifecycle APIs. Keep source evidence immutable or versioned; never silently rewrite history.

## Return

Report pack scope and trust domain, source identities, evidence artifact path, candidate
count and names, excluded categories, sensitivity and independent-review results, task-level
retrieval measurements, lifecycle outcomes, freshness triggers, and remaining authority.

## Enforcement

Self-enforced. Source approval, task authority, public memory lifecycle APIs, and the
independent memory-governance audit remain mandatory. This skill grants no access, mutation,
promotion, publication, or cross-domain reuse right.
