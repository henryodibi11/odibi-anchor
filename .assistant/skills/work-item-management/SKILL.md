# Work-item management

## When to load
Load for Problem framing, backlog/work-item lifecycle, managed decisions, delivery coordination, or multi-session handoff. Start with [the artifact workflow](references/backbone.md) and [proportional planning](references/planning.md); use [multi-session](references/multi-session.md), [memory saving](references/memory-saving.md), [greenfield](references/greenfield.md), [implementation](references/implementation.md), [integration](references/integration.md), [migration](references/migration.md), or [refactoring](references/refactoring.md) detail when material.

When Asana is the target work-management system, you MUST read and apply [Asana task authoring](references/asana-task-authoring.md) before drafting, creating, commenting on, or materially updating an Asana task or status.

## When NOT to load
Do not load for a requested formal implementation Spec body or merely because coding needs routine planning.

## Workflow
State outcome, scope, authority, owner, dependencies, acceptance evidence, risks, stop/reversal conditions, and next state. Apply the task's runtime `capture_guidance`. Preserve provider-neutral content before approved publication. Keep one authoritative state and handoff unresolved facts explicitly.

## Enforcement
Self-enforced. Global instructions apply. External publication requires explicit bounded approval.
