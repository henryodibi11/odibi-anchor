# Writing Specs

## When to load
Load only for an explicit request to write/update a Spec or when current policy requires a formal implementation contract. Follow [the preserved Spec workflow](references/backbone.md).

## When NOT to load
Never load merely because implementation needs planning, architecture is discussed informally, or code will change.

## Workflow
Anchor to the accepted Problem recommendation and revision; state outcome, non-goals, authority, exact contracts, files/interfaces, compatibility, data/effects, sequencing, evidence, tests, rollout, rollback, stop conditions, and unresolved decisions. Apply the task's runtime `capture_guidance`. Make implementation mechanical and trace every requirement to evidence.

## Enforcement
System policy may require a Spec. Global instructions apply. Writing or loading one does not prove acceptance or authorize implementation.
