# Deneb and Power BI Portability Guide

**Researched:** 2026-08-14 | **Baseline:** Deneb 1.9.1.0, Power BI Visuals API 5.11.0
**Evidence:** [S] MIT-licensed Deneb application source; [U] Power BI Desktop/Service runtime behavior

This guide separates source-confirmed packaging facts from behavior that must be exercised in Power BI.
The public Deneb documentation repository was not copied because no explicit redistribution license was
found. This is original synthesis; web links are provenance, not offline dependencies.

## Source-confirmed host contract

Deneb 1.9.1 declares:

- one data role named `dataset` with kind `GroupingOrMeasure`;
- categorical categories and values both bound to that role;
- a category data-reduction window of 10,000 rows;
- `supportsLandingPage`, `supportsMultiVisualSelection`, and `supportsHighlight`;
- enhanced tooltips with default and canvas support;
- no empty data view support;
- advanced edit mode level 2;
- required `ExportContent` privilege;
- configurable Vega/Vega-Lite provider, SVG/canvas render mode, tooltips, context menu, highlight,
  selection mode, maximum selected points, locale, and logging;
- bundled runtime versions read from installed Vega and Vega-Lite packages rather than hard-coded
  display strings;
- schema URLs derived from each bundled runtime's major version.

These facts come from `capabilities.json`, `pbiviz.json`, and the runtime source. They prove declared
capability, not successful behavior in every Power BI host.

## Portability pipeline

```text
typed intent
  → bounded pandas/Spark projection
  → Altair or Vega-Lite specification
  → remove Python-local data references
  → map fields to Deneb dataset names
  → validate target schema/runtime version
  → import/paste as Deneb spec or template
  → qualify rendering and host interactions in Power BI
```

Keep the host adapter separate from the visualization compiler. A standalone engine should emit valid
Vega-Lite/Vega plus a compatibility report; a Power BI adapter should own dataset naming, host features,
and qualification evidence.

## Dataset substitution

An Altair/Vega-Lite artifact often contains inline `values`, a named dataset generated by Altair, a
URL, or notebook data-server references. A Deneb-bound specification generally reads the host-provided
dataset:

```json
{
  "data": {"name": "dataset"},
  "mark": {"type": "bar"},
  "encoding": {
    "x": {"field": "Pipeline", "type": "nominal"},
    "y": {"field": "Duration (ms)", "type": "quantitative"}
  }
}
```

The field strings must match the fields exposed by the Deneb dataset after Power BI binding. Do not
assume original pandas/Spark column names survive display-name, measure, aggregation, or template
mapping decisions.

## Field-mapping manifest

Emit a companion mapping rather than silently rewriting names:

```json
{
  "target": "deneb",
  "data_name": "dataset",
  "fields": [
    {"logical": "pipeline", "host": "Pipeline", "kind": "column"},
    {"logical": "duration_ms", "host": "Duration (ms)", "kind": "measure"}
  ],
  "required_capabilities": ["tooltips"],
  "unverified_capabilities": ["cross_selection"]
}
```

This keeps generated code debuggable and allows a template importer to request explicit mappings.

## Data-shape constraints

- The declared 10,000-row window means large report datasets can be reduced before Vega sees them.
- Power BI measures may arrive already aggregated; a second Vega-Lite aggregate can change meaning.
- Categories and measures share the `dataset` role but retain different host semantics.
- Nulls, highlights, totals, and formatted display values can differ from raw source values.
- A valid specification can render correctly against sample data and fail against host field names or
  reduced data.

An engine should report expected grain, required fields, aggregation assumptions, and maximum useful
cardinality alongside the spec.

## Interaction boundary matrix

| Feature | Vega/Vega-Lite alone | Deneb source declaration | Required evidence |
| --- | --- | --- | --- |
| Internal hover/selection | Yes | selection configurable | Browser and Power BI interaction test |
| Conditional highlight | Yes | highlight supported | Host highlight payload test |
| Cross-visual selection | No host effect by itself | multi-visual selection declared | Power BI report test |
| Cross-filtering | No host effect by itself | implementation-specific | Power BI report test |
| Context menu | Event exists in Vega | context menu configurable | Right-click host test |
| Report tooltip | Vega tooltip differs | enhanced tooltips declared | Tooltip-page/default tooltip test |
| Hyperlink | Vega `href` possible | host security may intervene | Desktop and Service test |
| Widget binding | Vega HTML input | host embedding may not expose it | Power BI test or mark unsupported |

Never label a capability “Power BI supported” solely because the generated Vega-Lite works in a
browser or vl-convert.

## Render-mode decisions

| Mode | Strength | Risk |
| --- | --- | --- |
| SVG | Inspectable vector output, crisp text, easier static parity | Large mark counts can be expensive |
| Canvas | Better for many marks in some cases | Less inspectable and different tooltip/export behavior |

Deneb declares both SVG and canvas modes. Qualify performance and tooltip behavior with representative
data rather than selecting canvas automatically based only on row count.

## Template design

A reusable template should separate:

- specification body;
- logical-to-host field mappings;
- expected field kinds and semantic types;
- theme/config assumptions;
- supported Vega/Vega-Lite provider and major version;
- required Deneb/Power BI capabilities;
- known unsupported or unverified interactions;
- representative sample data kept outside proprietary environments.

Do not embed employer data, report identifiers, workspace URLs, or proprietary measures in a public
template.

## Compatibility report

Recommended engine output:

```json
{
  "status": "compatible_with_qualification",
  "target": "deneb-1.9",
  "provider": "vegaLite",
  "schema_major": 6,
  "rewrites": ["data source replaced with named dataset"],
  "warnings": ["selection controls internal marks; cross-filtering is unverified"],
  "required_host_tests": ["field mapping", "tooltip", "selection", "10k row reduction"]
}
```

Fail rather than emit when the target provider cannot represent a required feature. Warn when the spec
is structurally valid but host behavior remains unverified.

## Power BI qualification matrix

Exercise representative states in every host that matters:

1. Desktop authoring render.
2. Desktop selection, highlight, tooltip, and context menu.
3. Service render after publication, if publication is authorized.
4. Report filters and slicers changing the dataset.
5. No rows, one row, null-heavy rows, and reduced/large datasets.
6. Measure versus column bindings and renamed display fields.
7. SVG and canvas where both are supported.
8. Export to PDF/PowerPoint/image where required.
9. Theme/high-contrast/accessibility behavior.
10. Version metadata retained with screenshots or test records.

Documentation or source inspection cannot replace this host evidence.

## Failure diagnosis

| Symptom | Check first |
| --- | --- |
| Blank visual | provider/schema version, `dataset` name, field names, data reduction |
| Missing categories | 10,000-row reduction and upstream filters |
| Wrong totals | Power BI measure aggregation plus Vega-Lite aggregation |
| Selection does nothing externally | internal selection versus host selection bridge |
| Tooltip differs | Vega tooltip versus enhanced Power BI tooltip path |
| Works in editor, fails in Deneb | external URLs, unsupported bindings, runtime version mismatch |
| Export differs | render mode, fonts, host export limitations |
